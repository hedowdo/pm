# Frontend working guide

## Scope and current status

These instructions apply to the frontend demo in `frontend/`. Part 2 of `../docs/plan.md` renamed it from `front end/`, and Part 3 configured its static export for the FastAPI container; do not create a second competing frontend directory.

The current app is a single-board, client-rendered Kanban app protected by the Part 4 FastAPI session flow. The complete board is still persisted in browser `localStorage` under `kanban-mvp.board.v1`; it is not purely in memory. `readSavedBoard` only checks that parsed `columns` and `cards` are arrays, so it is not full schema validation. Part 7 replaces that browser persistence with FastAPI and SQLite.

Keep changes small, follow the root `AGENTS.md`, and add no feature outside the approved plan. Use no emojis in code, UI copy, tests, or documentation.

## Stack

- Next.js 16.3.1 App Router with React and ReactDOM 19.2.8.
- TypeScript in strict mode with `@/*` mapped to `src/*`.
- Tailwind CSS 4 through PostCSS and `@import "tailwindcss"`; there is no Tailwind configuration file.
- dnd-kit for pointer and keyboard drag-and-drop.
- Radix Dialog for the card editor.
- Lucide React for icons.
- Vitest 4, jsdom, Testing Library, and jest-dom for unit/component tests.
- Playwright with Chromium for the browser workflow.

Before using or changing a Next.js API, consult the matching local documentation in `node_modules/next/dist/docs/`. The target deployment is a static export created with `output: "export"`; FastAPI, not Next.js, owns runtime APIs and cookies.

## Board contract and invariants

- `ColumnId` is the fixed union `ideas | todo | in-progress | review | done`.
- The column IDs and their five-column order are stable. Only `title` is renameable.
- A `KanbanCard` has `id`, `title`, `details`, and `columnId`.
- Card order is the order of the single global `cards[]` array after filtering by `columnId`. The future API and database must preserve both column membership and within-column order.
- Card titles are required and trimmed. Details are optional and trimmed to an empty string when blank.
- A blank column rename is discarded and the prior title is restored.
- Card deletion requires explicit confirmation.
- New manual card IDs use `crypto.randomUUID()` and the backend validates uniqueness when the complete board is saved. AI-created card IDs are generated by the backend.
- Dropping a card over another card inserts it before that card.
- Dropping a card on a column appends it to that column.
- Moving across columns updates `columnId`; moving within a column changes order.

Do not add column creation, deletion, or reordering. The AI MVP may create, edit, and move cards, but may not delete cards or change the fixed column structure.

## Rendering and interaction conventions

- `KanbanBoard` is a client component because it owns reducer state, effects, dialogs, and drag-and-drop.
- Browser APIs must be accessed only in client-safe effects or event handlers so static prerendering continues to work.
- Pointer dragging begins after 6 pixels; keyboard dragging uses `sortableKeyboardCoordinates`.
- Only the grip button owns drag listeners. Clicking the rest of a card opens its editor.
- Preserve accessible labels used by users and tests, including `Rename ...`, `Add card to ...`, `Drag ...`, `Column name`, `Card title`, and `Details`.
- Preserve `data-testid="column-{id}"` and `data-testid="kanban-card"` unless tests are intentionally migrated to a better accessible query.
- Maintain keyboard and focus behavior when touching dialogs, rename controls, drag handles, and the future chat drawer.
- The current clickable card container is a non-interactive `article`; when that component is next changed, correct its keyboard activation without disrupting the nested drag button.

## Styling conventions

- Required palette:
  - yellow `#ecad0a`
  - blue `#209dd7`
  - purple `#753991`
  - navy `#032147`
  - gray `#888888`
- Global CSS variables define the core palette, while the current component also uses Tailwind arbitrary color utilities.
- Body text uses Arial/Helvetica; `.editorial-title` uses Georgia/Times.
- The design uses a warm paper background, subtle radial gradients, navy column headers, white cards, rounded panels, and restrained shadows.
- The five-column board has a 1420px minimum width and scrolls horizontally on smaller screens. Preserve deliberate horizontal board behavior unless the approved responsive chat design requires an evidence-based adjustment.
- Review and Done currently use coral and green dot accents in addition to the required core palette.
- Reuse the existing design language for sign-in and chat rather than introducing another visual system.

## Static frontend and API boundaries

- The final Next.js output is static and served by FastAPI at `/`.
- Use same-origin relative paths beginning with `/api`; do not hardcode a backend host or development port.
- FastAPI owns `/api`, credential validation, session cookies, SQLite access, OpenRouter calls, and all board authorization.
- Render the board only after `GET /api/auth/me` confirms the session. Keep the hardcoded credential pair and comparison logic out of frontend source and bundles.
- Do not add Next.js API routes, request-dependent route handlers, server actions, proxy rules, runtime cookies, or other features that require a Node server.
- The browser must never receive `OPENROUTER_API_KEY` or call OpenRouter directly.
- Until Part 7, preserve the existing `localStorage` demo behavior. In Part 7 remove it completely so stale browser state cannot overwrite SQLite.
- After Part 7, every mutation uses the backend and replaces/reconciles with the authoritative board returned by the API.
- AI chat history alone uses `sessionStorage` in Part 10 and is cleared on logout. Board state never uses `sessionStorage`.

## Commands and verification

From the frontend directory:

```sh
npm run dev
npm run lint
npm test
npm run build
npm run test:e2e
```

Set `PLAYWRIGHT_BASE_URL=http://127.0.0.1:8000` using the current shell's environment syntax to run Playwright against the Docker container. Without it, Playwright starts the local Next.js development server.

Required verification depends on the change:

- Pure board logic: reducer tests.
- UI interaction or accessibility: component tests.
- Drag-and-drop, routing, auth, persistence, or chat workflow: Playwright plus the relevant lower-level tests.
- Configuration or static-serving change: lint, unit tests, `next build`, and container/static-asset smoke tests.

Verification observed on 2026-08-15 after Part 4:

- Lint passed.
- All 13 Vitest tests passed.
- All 7 FastAPI tests passed in the locked Python container environment.
- The Part 3 production build uses `output: "export"` and writes the static site to `out/`.
- The container-backed Playwright workflow passed authentication, refresh, board editing and drag behavior, logout, and board-persistence checks. Setting `PLAYWRIGHT_BASE_URL` skips the local Next.js development server, so the earlier development-server memory failure did not reproduce.
- Same-column browser coverage uses the supported keyboard sensor to move the current second card above the first, which proves a real order change under the reducer's insert-before rule.
